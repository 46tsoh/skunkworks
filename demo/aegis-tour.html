two engines, one verdict

  
A graph of agents and a hypothesis loop

  
Both engines share one knowledge base and one decision router, so a finding seen by each is deduplicated across them and the report ranks a single, unified verdict.

  

    

      
Dynamic engine Strix-style

      
A graph of agents spawns a subagent per confirmed-exploitable lead, emitting a live transcript of prose, tool calls and typed decisions.

      
  • routing via DecisionRouter.choose
  • selects the real tool adapters with --use-tools
  • streams events.jsonl, tailed live by the dashboard

    

    

      
Static engine RAPTOR-style

      
A researcher scores and investigates a hypothesis queue over source, running SAST and SCA tooling offline.

      
  • priority via DecisionRouter.score
  • semgrep · CodeQL dataflow · Trivy SCA
  • triage → posterior → dedupe → validate → score

safety by construction

  
The planner proposes; a clamp disposes

  
Whatever the model returns, a pure clamp admits only tokens drawn from a trusted set fixed before the run. A hostile goal can reorder or prune, but can never add a phase, author an argument, change the target, or widen scope.

Default-deny scope
Scope is operator-declared data, never inferred from a page or a finding — and it never auto-expands.

    
Gated on exact bytes
Every live action re-checks authorize() on the precise target the tool will receive.

    
Proof, not damage
No destruction, no persistence, no exfiltration beyond in-scope proof. Verify and stop.
